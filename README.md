## What is Sigil?

Sigil is an **on-chain authorization gate** for autonomous agents that
proves an action is permitted by a private policy — without ever
publishing the policy, the principal's identity, or the secret that
binds them. It ships as a small, composable family of Midnight-native
privacy contracts: a **gate** that enforces a private policy envelope,
and a **registry** that records a privacy-preserving (principal, agent)
delegation graph.

### The gate

An agent publishes a *sigil*: a commitment to a policy (allowlist,
spend caps, expiry, pause flag). Later, every action the agent wants
to take flows through `authorize(...)`, a Compact circuit that:

1. **Proves identity** — the agent proves it holds the principal's
   secret, derived into a stable public key.
2. **Proves the policy matches** — the contract checks the policy
   commitment is registered and bound to that principal.
3. **Proves the intent fits the envelope** — target allowed, selector
   allowed, value under the per-call cap and daily cap, policy not
   paused, not expired.
4. **Prevents replay** — every successful authorization burns a
   nullifier derived from the secret and the request id.

The policy contents, the principal's secret, and the PIN never leave
the agent's prover. The public ledger only sees the policy commitment,
the authorization counter, and the nullifier set.

### The registry

The principal proves control of the same secret and authorises or
revokes agent commitments under their identity. Agent commitments are
opaque on-chain — recorded as a `(principal, agent) pair-hash` with a
domain-separated tag — so the registry reveals only membership, not
the secret-derived materials. A revocation records the pair-hash in a
separate set so a revoked agent cannot be silently re-registered.

Together, the two contracts cover the two questions a delegated agent
must answer on-chain: *am I the right agent for this principal?* (the
registry) and *is this action inside my authorised envelope?* (the
gate).

## Why Midnight?

On a transparent chain, the same gate leaks the policy it is supposed
to protect. An agent's allowlist, spend caps, and risk thresholds are
its competitive strategy — publishing them lets adversaries front-run,
game, or copy the agent. Sigil flips the model with Midnight's
zero-knowledge dual-ledger:

- **Private state** holds the policy and the secret.
- **Public state** holds only commitments and counters.
- **ZK proofs** carry the verification across the boundary.

## Build and test

Requires Node 20+ and the [`compact` compiler
0.31.x](https://docs.midnight.network/compact).

```sh
# Install everything
npm install

# Compile every Compact contract (generates src/managed/ in each package)
npm run compact

# Build the TypeScript runtime (simulators) so dist/ is populated
npm --dir contract         run build
npm --dir contract-registry run build

# Run every test suite (13 gate + 14 registry = 27 cases)
npm test
```

## Security model

The `authorize` circuit checks time against the **on-chain** `blockTimeGte`
/ `blockTimeLte` oracles from the Compact standard library, never
against a prover-supplied witness. A malicious agent cannot:

- claim a `currentTime` after the block to forge a future-dated
  authorization, or
- bypass an expired policy by lying about the wall clock.

Every hash in Sigil carries an explicit domain tag (`sigil:pk:`,
`sigil:nul:`, `sigil:reg:principal:`, `sigil:reg:pair:`,
`sigil:reg:revoke:`, `sigil:reg:register:`) so commitments and
nullifiers from one contract cannot be replayed against another in the
same family.

## Roadmap

This submission ships the gate and the registry as two independent
contracts. The next natural steps are:

- **Cross-contract composition.** Let a deployed gate consult a
  registry's `isAgentAuthorized` in-circuit, so a sigil is only
  honoured if the agent is currently authorised by that principal.
- **Multi-rule policies.** Replace the single-rule policy in the
  gate with a bounded list of (target, selector, perCallCap) triples.
- **Compliance attestation.** A third contract that produces a
  selective-disclosure receipt a regulator can verify without
  revealing which actions or which policy were used.
- **Web UI + deploy.** A React + Lace frontend backed by a deployed
  Preprod address.
